# Раздел «Управление»

## Назначение

URL: `/rights/`. Доступен только администраторам. Создание и редактирование
сервисов предназначено для desktop-интерфейса и скрыто на mobile.

## Каталог и health

Карточки показывают тот же health-status, что и `Сервисы`. Кнопка со стрелкой
сбрасывает глобальную раскладку. Pin/unpin позволяет перемещать карточки по слотам.
Сохранённая раскладка применяется ко всем пользователям.

## Добавление сервиса

Кнопка `Добавить сервис` открывает модальное окно. Поддерживаются:

- защищённый reverse proxy;
- внешняя ссылка.

Для reverse proxy задаются домен, upstream, иконка, health-check, nginx-опции и
режим конфигурации. DNS должен уже указывать на HUB для выпуска сертификата.

## Операции формы

- `Сохранить черновик` — сохраняет модель/ревизию без публикации финального vhost;
- `Сохранить и проверить` — строит конфиг и выполняет проверку без включения;
- `Применить` — проверяет, записывает vhost, включает symlink, reload nginx и
  фиксирует ревизию;
- `Получить сертификат` — запускает certbot для сохранённого reverse proxy;
- `Проверить nginx` — выполняет серверную проверку текущей конфигурации.

Создание и применение являются разными состояниями. После первого сохранения
форма должна перейти в режим редактирования уже созданного объекта, а не пытаться
создать второй сервис с тем же доменом.

## Вкладка «Основное»

- тип сервиса;
- название и описание;
- domain/upstream либо external URL;
- иконка;
- порядок;
- active/enabled flags;
- preflight URL.

Внутренние адреса видит только администратор в management UI.

## Вкладка «Проверка»

- HTTP, HTTPS или TCP;
- host, port и path;
- timeout;
- допустимые HTTP-коды;
- interval;
- порог ошибок и успехов;
- пути сертификата.

`Принудительно проверить` запускает одну server-side проверку и обновляет статус.

## Вкладка «Опции nginx»

Управляемые функции объединены в группы и профили. Для каждой опции отображаются
рекомендация, зависимости, конфликты и кнопка `Подробнее` с примерами применения.

Выбирайте только нужные функции. Опция может автоматически включить dependency
или исключить несовместимую функцию. Итоговый конфиг всегда проверяется через
`nginx -t`.

## Вкладка «Ручной режим»

В managed mode конфиг строится из безопасных шаблонов. Manual mode принимает
полный nginx-конфиг администратора и предназначен для редких несовместимых
upstream.

Manual mode увеличивает риск:

- обхода `auth_request`;
- раскрытия cookie;
- SSRF/open proxy;
- конфликта vhost/port;
- поломки reload nginx.

Используйте его только после review и backup.

## Вкладка «Ревизии»

Хранит снимок полей и итоговый rendered config. Можно открыть предыдущую ревизию
для сравнения/восстановления формы. Ревизия не заменяет системный backup.

## Контекстное меню карточки

- редактировать;
- принудительно проверить;
- включить/отключить;
- удалить.

Удаление reverse proxy убирает DB-запись, vhost/symlink и сертификат выбранного
домена через root helper. Удаление необратимо; сначала убедитесь, что домен не
используется другим приложением.

## Требования перед публикацией

1. DNS уже резолвится на HUB.
2. Upstream доступен с сервера.
3. Domain входит в разрешённый suffix.
4. Порты 80/443 доступны для ACME.
5. Текущий `nginx -t` успешен.
6. Сертификат выпущен.
7. После применения `hubctl doctor` успешен.
