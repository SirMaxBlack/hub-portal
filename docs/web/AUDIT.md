# Раздел «Журнал»

## Назначение

URL: `/rights/logs/`. Только для администраторов. Журнал read-only, кроме полной
операции очистки.

## Что записывается

- успешные и неуспешные входы;
- logout;
- смена пароля;
- token actions;
- session actions;
- создание/изменение/архив пользователя;
- административные действия;
- один факт открытия карточки сервиса;
- отрицательная проверка прямого service access.

Действия внутри CRM/NetBox/другого downstream не детализируются. Assets, API
polling, heartbeat, favicon и health monitor не должны раздувать бизнес-журнал.

## Колонки

- кто;
- когда;
- IP;
- куда;
- метод авторизации;
- результат.

Клик по строке открывает детали: URL/path, method, status, User-Agent, request ID
и metadata, если они были сохранены.

## Фильтры

- период: сегодня, 24 часа, 7/30 дней, произвольный;
- пользователь;
- IP;
- нормализованная категория;
- тип: portal, service open, service gate;
- метод входа;
- результат;
- размер страницы 25/50/100.

По умолчанию показываются последние 7 дней.

## CSV

`Экспорт CSV` выгружает текущую отфильтрованную выборку, а не весь журнал вне
фильтров. Файл может содержать персональные данные и должен храниться защищённо.

## Очистка

Нужно ввести точную фразу `ОЧИСТИТЬ`. Операция:

1. Ставит runtime maintenance lock.
2. Временно отключает запись нового audit и HUB project logs.
3. Удаляет `AuditEvent`.
4. Обнуляет текущие HUB nginx logs и удаляет их rotated copies.
5. Возвращает logging mode.
6. Снимает lock даже при попытке recovery.

Другие пользователи продолжают работать, но события в коротком окне очистки
намеренно не сохраняются. Пользователи, сервисы, sessions и MariaDB в целом не
очищаются.

## Хранение

Старые записи автоматически удаляет `hub-portal-prune-audit.timer`. Default
retention — 180 дней и задаётся `HUB_PORTAL_AUDIT_RETENTION_DAYS`.
