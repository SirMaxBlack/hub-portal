# Раздел «Сервисы»

## Назначение

URL: `/services/`.

Это рабочий каталог пользователя. Обычный пользователь видит только назначенные
ему активные сервисы. Администратор видит весь активный каталог.

## Метрики

Для пользователя:

- назначено;
- доступно;
- недоступно;
- проверяется.

Для администратора первая метрика показывает общее число сервисов.

## Карточка

Карточка содержит только иконку и название. Внутренний IP, upstream и домен не
показываются. Цвет отражает health-status, а не наличие права.

Нажатие ведёт сначала на `/services/<slug>/open/`. Backend повторно проверяет:

- сессию;
- обязательную смену пароля;
- право пользователя;
- active/enabled state;
- подтверждённый health-status.

Frontend-ссылка не является механизмом безопасности.

## Поведение статусов

- `up` — redirect разрешён;
- `down` — карточка недоступна и backend не открывает service-domain;
- `unknown` — открытие разрешается, потому что отсутствие свежей проверки не
  доказывает недоступность.

Статусы запрашиваются через `/api/services/statuses/` только для видимых текущему
пользователю сервисов.

## Раскладка

Позиции задаёт администратор в `Управлении` и они общие для всех учётных записей.
Если пользователю доступна одна карточка, она сохраняет глобальный slot, а не
растягивается на весь контейнер.

## Reverse proxy и внешняя ссылка

Reverse proxy открывается под сервисным доменом и продолжает проходить nginx
authz. Внешняя ссылка покидает HUB после redirect; её доступность и дальнейшая
защита зависят от внешнего сайта.
