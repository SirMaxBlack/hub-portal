# Раздел «Безопасность»

## Назначение

URL: `/security/`. Доступен только администраторам.

## «Доступ к HUB»

Глобальный список IP/CIDR определяет, кто может увидеть форму входа и обращаться
к защищённым service-domain.

Примеры:

```text
203.0.113.25/32
192.168.10.0/24
2001:db8:10::/64
```

Кнопка `+ Добавить адрес` создаёт обязательную непустую строку. `−` удаляет
строку. Пустая таблица означает доступ с любых адресов.

Перед сохранением restricted-списка добавьте `Текущий IP`, иначе можно закрыть
себе web-доступ. Сохраняйте альтернативный административный путь через console
или SSH.

## «Допустимое количество ошибок при авторизации»

Переключатель включает/отключает password login protection. Настраиваются:

- разрешённое число ошибок, 1–25;
- время блокировки;
- единица времени от секунд до дней.

В summary показываются текущие значения и число активных блокировок учёток и
browser identities.

Ограничение применяется к логину/паролю. Token login не увеличивает counter.

## «Управление ограничениями»

`Сброс ограничений` удаляет все активные user/browser lock states. Пользователи
сразу снова могут пытаться войти. Включение или отключение механизма также
сбрасывает прежние ограничения, чтобы старое состояние не сработало неожиданно.

Для одного пользователя используйте `Снять блокировку авторизации` в его
вкладке `Безопасность`.

## Персональный IP-доступ

Настраивается не здесь, а в `Пользователи -> пользователь -> Безопасность`.
Персональный список является дополнительным к глобальному:

```text
global allow AND user allow
```

## Экстренное восстановление доступа

Если ошибочный allowlist закрыл web-интерфейс, нужен SSH/console и изменение
данных через штатный Django shell/management command. Не открывайте MariaDB
наружу и не удаляйте таблицы. Перед ручным восстановлением создайте DB dump.

Полная модель угроз: [`../SECURITY_MODEL.md`](../SECURITY_MODEL.md).
