# Django admin

## Назначение

URL: `/admin/`. Это низкоуровневый служебный интерфейс Django, а не основной
раздел управления HUB.

Для обычной работы используйте `Управление`, `Пользователи`, `Журнал` и
`Безопасность`: там действуют проверки, связанные операции, audit и безопасные
root helpers.

## Когда применять

- аварийная read-only диагностика моделей;
- просмотр данных, для которых ещё нет штатного интерфейса;
- восстановительные действия по отдельной проверенной инструкции.

## Риски

Прямое изменение моделей через Django admin может обойти составную бизнес-логику:

- завершение sessions при отключении пользователя;
- отзыв token при архивировании;
- генерацию и проверку nginx-конфига;
- выпуск/удаление сертификата;
- создание service revision;
- нормализованный business audit.

Не удаляйте пользователей, сервисы, sessions, access rules и audit вручную без
backup. Для сервисов особенно нельзя считать изменение DB-записи публикацией:
nginx-vhost и сертификат управляются отдельным root helper.

## Безопасность

- не публикуйте `/admin/` как отдельный домен;
- доступ ограничивается теми же глобальными CIDR и HTTPS-контуром HUB;
- не выдавайте Django staff/superuser без необходимости;
- используйте уникальную admin-учётку и просматривайте журнал после аварийных
  операций.
